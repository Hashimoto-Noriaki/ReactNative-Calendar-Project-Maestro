## 指示

以下の 3 つのチェックを実行し、結果をまとめて報告してください。

1. Lint: `npm run lint`（`expo lint` と `prettier --check .`。Markdown の整形崩れ、frontmatter 直後の空行抜けなども検出する）
2. ユニットテスト: `npm test -- --ci`（Jest）
3. 型チェック: `npm run type-check`（`tsc --noEmit`）

### 実行ルール

- 3 つは互いに依存しないので、並列に実行してよい
- 1 つが失敗しても残りのチェックは最後まで実行する（途中で止めない）
- 引数でファイルやテスト名が指定された場合は、Jest をその対象に絞って実行する（例: `npx jest <path>`）。Lint と型チェックはプロジェクト全体で実行する
- 失敗しても、ユーザーの指示がない限りコードを自動修正しない（原因と修正案の提示にとどめる）

### 報告フォーマット

```
## チェック結果

| チェック | 結果 |
| --- | --- |
| Lint | ✅ / ❌（エラー n 件・警告 n 件） |
| Jest | ✅ / ❌（成功 n / 失敗 n） |
| 型チェック | ✅ / ❌（エラー n 件） |
```

失敗があった場合は、表の下にチェックごとに以下を記載する:

- 該当ファイルと行番号（`path:line` 形式）
- エラーメッセージの要点
- 考えられる原因と修正案

すべて成功した場合は「すべてのチェックが通りました（PR マージ条件を満たしています）」と一言添える。
