# アーキテクチャ

Googleカレンダークローン（Expo / React Native）のシステム構成と設計方針をまとめる。

## 全体構成

サーバーは持たず、予定データは端末内で完結させる。

```text
┌──────────────────────────────┐
│ src/app/（Expo Router：画面）  │  ルーティング・画面の組み立てのみ
└──────────────┬───────────────┘
               │
┌──────────────▼───────────────┐
│ src/features/{domain}/        │  UI コンポーネント・hooks・状態・純粋関数
└──────────────┬───────────────┘
               │
┌──────────────▼───────────────┐
│ ストレージ層（端末内）          │  予定・カレンダー・設定の永続化
└──────────────────────────────┘
```

## フォルダの役割

| パス                     | 役割                                                                              |
| ------------------------ | --------------------------------------------------------------------------------- |
| `src/app/`               | 画面（ファイル = 画面、`_layout.tsx` = ナビゲーター）。画面以外のコードは置かない |
| `src/features/calendar/` | 月 / 週 / 日 / スケジュール表示、日付ナビゲーション、日付計算                     |
| `src/features/events/`   | 予定の作成・編集・削除・詳細、繰り返し予定の展開                                  |
| `src/features/settings/` | 設定（週の開始曜日・表示するカレンダーなど）                                      |
| `src/components/`        | 複数 feature で共通の UI パーツ                                                   |
| `src/hooks/`             | 複数 feature で共通のフック（`useTheme` など）                                    |
| `src/constants/`         | テーマ・定数                                                                      |

各 feature フォルダには、コンポーネント・hooks・types・utils・テストを同じ場所に置く（Co-location）。

```text
src/features/events/
├── components/
│   ├── event-card.tsx
│   └── event-card.test.tsx
├── hooks/
│   └── use-events.ts
├── utils/
│   ├── expand-recurrence.ts
│   └── expand-recurrence.test.ts
└── types.ts
```

## 画面遷移（予定）

```text
(tabs)
├── カレンダー（月 / 週 / 日 / スケジュールを切り替え）
│     ├── 日付タップ → 日表示
│     ├── 予定タップ → 予定詳細 ─→ 予定編集
│     └── ＋ボタン   → 予定作成（モーダル）
└── 設定
```

- 画面遷移は `expo-router` の `Link` / `router`、パラメータは `useLocalSearchParams` を使う
- 予定詳細・編集は `events/[id]` のような動的ルートで扱う
- 作成・編集画面はモーダル表示を想定する

## 状態管理

| 状態         | 内容                                                    | 持ち方                           |
| ------------ | ------------------------------------------------------- | -------------------------------- |
| 予定データ   | `CalendarEvent[]`・`Calendar[]`                         | アプリ全体で共有（方式は未決定） |
| 表示状態     | 選択中の日付・表示モード（月 / 週 / 日 / スケジュール） | アプリ全体で共有                 |
| 画面ローカル | フォーム入力中の値など                                  | コンポーネント内の `useState`    |

> **未決定:** 共有状態の実装方式（React Context + `useReducer` / Zustand など）。決まったらこの節を更新する。

## データ保存

- 保存先は端末内のみ（サーバー / DB は作らない）
- 日時は ISO 8601 文字列で保存する（詳細は [data-model.md](./data-model.md)）
- 保存データにはスキーマバージョンを持たせ、構造変更時にマイグレーションできるようにする

> **未決定:** 保存先（AsyncStorage / expo-sqlite など）。予定数が増えたときの検索性能と実装コストを比べて決める。

## 設計方針

### 日付計算は純粋関数にする

週の開始日・月の日数・カレンダーのグリッド生成・繰り返し予定の展開などは、UI から切り離した純粋関数として `utils/` に置き、Jest でテストする。現在時刻が必要な関数は引数で受け取り、テストで固定できるようにする。

### タイムゾーン

- 時刻付きの予定はタイムゾーン情報付きの ISO 8601（例: `2026-10-03T10:00:00+09:00`）で保存する
- 終日予定は日付のみ（例: `2026-10-03`）で保存し、タイムゾーンの影響を受けないようにする
- 表示時に端末のタイムゾーンへ変換する

### UI

- 長いリスト（スケジュール表示・予定一覧）は `FlatList` / `SectionList` を使う
- 月・週の切り替えスワイプは `react-native-gesture-handler`、アニメーションは `react-native-reanimated` を使う
- 色・余白は `src/constants/theme.ts` と `useTheme` から取得し、ライト / ダークモード両方に対応する

### プラットフォーム

- iOS / Android を主対象とし、Web も動作する範囲で対応する
- プラットフォーム差分はファイル拡張子（`.web.tsx` など）か `Platform.select` で分ける

## テスト

| 種類        | ツール                              | 対象                                      |
| ----------- | ----------------------------------- | ----------------------------------------- |
| ユニット    | Jest + React Native Testing Library | 日付計算の純粋関数・コンポーネント・hooks |
| E2E         | Maestro（予定）                     | 予定の作成〜削除など主要フロー            |
| UI カタログ | Storybook                           | コンポーネントの見た目確認                |
